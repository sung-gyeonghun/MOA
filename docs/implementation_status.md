# 모아 구현 현황

2026-10-13. 목표는 실제 공연 데이터 연결을 포함한 Android 앱 완성입니다.

## 구현

- Kotlin, Compose Material 3, MVVM, Coroutines/Flow, Hilt, Navigation Compose
- 발견, 검색, 상세, 찜, 설정과 필터 바텀시트
- 지역·복수 장르·오늘/주/주말/월/직접 기간 필터
- 공연명·출연진 검색, 검색 기록과 삭제, 시작일·종료일 정렬
- Room 찜 및 실제 공연 캐시, DataStore 선호 설정·데이터 주소
- Retrofit/OkHttp JSON 연결, Coil 포스터 및 로드 실패 대체 아트워크
- 공식 예매처 목록, 외부 브라우저 이동, 누락 필드와 빈 결과 안내
- Python KOPIS 수집, 월 경계 포함·ID 중복 제거·검증 후 Pages 배포 워크플로
- 개발용 서명 APK와 용량 최적화 preview 빌드

## 검증

- Debug APK 빌드 성공
- R8·리소스 축소 Preview APK 빌드 성공, 약 5 MB (정확한 크기와 SHA256은 docs/verification/artifacts.json)
- 최적화 APK 설치 후 홈·검색·상세·찜·설정 화면 실행 확인, AndroidRuntime 오류 없음
- Kotlin 필터·검색 단위 테스트 4개 통과
- Python 정규화·예매 URL·월 경계·빈 데이터 보호·파일 교체 롤백·출력 경로 보호·키 로그 보호 테스트 8개 통과
- Android 16 에뮬레이터 Compose 및 저장소 통합 테스트 11개 통과
  - 검색 → 상세 → 찜 → Activity 재생성 후 유지 → 삭제
  - 없는 검색어에 빈 결과 표시
  - 대구 + 콘서트/뮤지컬 복수 선택 및 Activity 재생성 후 선호 유지
  - 실제 HTTPS/Retrofit로 월별 데이터를 읽고 ID 중복 제거
  - 서버 종료 후 Room을 다시 열어 오프라인 캐시와 갱신 시각 복원
  - HTTP 503·JSON 파싱 실패·빈 목록·버전 변경·잘못된 날짜에 기존 캐시 보존
  - DataStore 파일과 Room을 다시 열어 설정·검색 기록·찜 유지
  - 버전 1 DB의 찜을 유지하는 버전 2 마이그레이션
  - 5,000건 합성 데이터의 캐시 로드 2초 이내 확인 (실제 전국 데이터 성능은 별도 검증 필요)
  - 예매처 선택 시 제공 URL을 그대로 브라우저 핸들러로 전달
  - 브라우저 부재 시 오류 안내, 강제 종료 방지
- Android 정적 검사 오류 0건. 의존성 최신 버전 및 SDK 관련 경고는 남아 있음
- Preview 정적 검사 오류 0건, 경고 14건 (주로 의존성 업데이트와 SDK 관련)
- 홈·검색·상세·찜·설정·필터 화면을 에뮬레이터에서 직접 캡처·확인
- 시스템 글꼴 150%에서 홈·검색·필터 화면 실행 및 배치 확인
- 필터 선택 상태와 찜 상태의 스크린 리더 설명 제공
- 미서명 Release APK/AAB 빌드 성공 (소유자 정식 서명키 미설정)

## 남은 외부 작업

사용자가 KOPIS 서비스키를 아직 발급·등록하지 않았다고 확인했습니다. 앱은 가상 체험 데이터로 동작합니다.

1. KOPIS 키 발급 및 데이터·포스터 재배포 조건 확인
2. GitHub Actions Secrets에 KOPIS_API_KEY 등록, Pages Source 설정
3. 코드 업로드 후 실제 수집과 공개 JSON 검증
4. 실제 데이터 커버리지·요청량·파일 크기·예매 링크 확인
5. 실제 기기 검증, 출시 서명키와 Play 배포 준비

실제 API 요청, 공개 Pages 배포, 실기기 시험 및 Play 출시를 완료했다고 주장하지 않습니다. 실제 데이터로 확인할 때까지 증분 수집은 사용하지 않고 전체 동기화합니다.
