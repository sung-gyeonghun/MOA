# 전국 공연 통합 조회 앱 — 요구사항 명세서 (PRD v1.0)

- 작성일: 2026-10-12
- 목적: 전국의 콘서트, 가수 전국투어, 뮤지컬, 연극 등 공연을 한곳에서 탐색하는 Android 앱
- 초기 사용자: 개발자 본인 (추후 일반 공개 고려)
- 핵심 기술: Kotlin, Jetpack Compose, Python, GitHub Actions, GitHub Pages, KOPIS OpenAPI
- 1차 범위: 공연 조회·검색·필터·상세·즐겨찾기·예매처 이동
- 제외: 로그인, 결제, 티켓팅 매크로, 취소표 감시, 서버 기반 푸시 알림

## 1. 프로젝트 목표

사용자는 여러 예매 사이트를 방문하지 않고도 전국의 공연을 지역·장르·날짜별로 찾아보고, 상세 정보를 확인한 뒤 공식 예매처로 이동할 수 있어야 한다.

### 대표 사용자 시나리오

1. **지역 탐색:** 앱 실행 → 대구 선택 → 콘서트·뮤지컬 확인 → 상세 보기 → 예매처 이동
2. **가수 검색:** ‘악뮤’ 검색 → 관련 공연 목록 → 날짜·지역 비교 → 즐겨찾기
3. **주말 탐색:** 이번 주말 선택 → 해당 기간 공연 표시 → 지역·장르 추가 필터

### 3.1 필터 동작 규칙

- 지역 미선택 시 전국을 표시한다.
- 장르 미선택 시 전체 장르를 표시한다.
- 장르 내 복수 선택은 OR, 지역·날짜·장르 간 조합은 AND 조건이다.
- 날짜 필터는 공연 기간과 선택 기간이 겹치는 공연을 포함한다.
- 지역 및 장르 선호는 DataStore에 저장하여 재실행 후에도 유지한다.
- 공연 장르 분류는 실제 KOPIS 제공 코드와 매핑한다.

## 4. 화면 요구사항

| 화면 | 주요 요소 | 진입 경로 |
|---|---|---|
| 홈 | 공연 카드 목록, 지역·장르·날짜 필터 | 앱 실행 |
| 검색 | 검색창, 검색 결과, 빈 결과 안내 | 하단 탐색 |
| 상세 | 포스터, 제목, 출연진, 기간, 가격, 장소, 예매처, 즐겨찾기 | 공연 카드 선택 |
| 즐겨찾기 | 저장한 공연 목록 및 삭제 | 하단 탐색 |
| 설정 | 기본 지역·관심 장르·데이터 갱신 정보 | 하단 탐색 |

- Navigation Compose로 화면을 연결한다.
- 홈·검색·즐겨찾기에서 같은 상세 화면으로 이동한다.
- 필드가 누락되면 ‘정보 없음’ 등 적절한 대체 문구를 사용한다.
- 포스터가 없거나 로드 실패 시 기본 이미지를 표시한다.
- 예매 URL이 없으면 예매 버튼을 숨기거나 비활성화하고 이유를 안내한다.

## 5. 시스템 아키텍처

```text
KOPIS OpenAPI (및 추후 허용된 데이터 소스)
          |
          v
GitHub Actions + Python
  - 정기 API 호출
  - 데이터 정규화 / 중복 제거
  - 오류 검증 / JSON 생성
          |
          v
GitHub Pages (정적 JSON 배포)
          |
          v
Android 앱 (Kotlin + Compose)
  - Retrofit / OkHttp
  - Room 로컬 캐시·즐겨찾기
  - DataStore 사용자 설정
```

**역할 구분:** GitHub Actions는 예약된 시점에 데이터를 갱신하는 작업 실행기이고, GitHub Pages는 결과 JSON을 제공한다. 별도 상시 실행 Spring Boot 서버는 v1.0에서 사용하지 않는다.

### 5.1 데이터 수집 정책

| 항목 | 요구사항 |
|---|---|
| 초기 주기 | 하루 1회 예약 실행 — 한국 시간 09:17 (지연 가능, 2026-10-13 사용자 요청 반영) |
| 범위 | 전국의 진행·예정 공연 |
| 중복 기준 | KOPIS 공연 고유 ID |
| 수정 반영 | 변경일 필터 검증 후 증분 수집 및 정기 전체 동기화 |
| 수집 실패 | 이전 정상 배포 데이터 유지 |
| API 키 | GitHub Actions Secrets 사용, 앱/공개 JSON에 포함 금지 |
| 실행 방식 | schedule + workflow_dispatch |
| 로그 | 수집 건수, 실패 사유, 실행 시각 기록 |
| 데이터 공개 | GitHub Pages의 공개 접근 및 API 재배포 허용 조건 확인 |

### 5.2 배포 파일 구조 (초안)

```text
public/
  manifest.json
  performances/
    2026-10.json
    2026-11.json
    2026-12.json
  details/
    PF123456.json
    PF123457.json
```

- `manifest.json`: 데이터 버전, 최종 갱신 시각, 파일 목록
- `performances/YYYY-MM.json`: 월별 공연 요약
- `details/{id}.json`: 공연별 상세
- 전국 데이터의 실제 크기와 갱신 빈도를 측정한 후 분할 방식 확정
- 여러 달에 걸친 공연은 조회 누락이 없도록 기간 중복 또는 별도 인덱스 정책을 적용

## 10. 개발 전 검증이 필요한 리스크

1. **공연 포괄 범위:** KOPIS가 모든 콘서트·전국투어를 누락 없이 제공하지는 않을 수 있다. 실제 데이터 샘플 검증 필요.
2. **정보 반영 시점:** 공연 최초 발표 및 티켓 오픈 전에 데이터가 등록된다는 보장이 없다.
3. **이용 권한:** API 호출뿐 아니라 JSON 재배포·포스터 노출·예매처 링크 사용 조건을 확인해야 한다.
4. **데이터량:** 월별 파일 크기, 공연 상세 요청량, 앱 검색 속도를 측정한 뒤 인덱스 및 분할 구조를 확정한다.
5. **예약 실행:** GitHub Actions의 cron은 UTC 기준이며 예약 시각이 지연되거나 실행이 누락될 수 있다.
